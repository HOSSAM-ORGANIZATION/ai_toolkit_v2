## 2. Directory Layout & Layer Boundaries

```text
lib/
├── core/ (or shared/)          # Cross-cutting primitives, theme, network, DI
│   ├── configs/                # Tokens (colors, fonts, dimensions), router, theme
│   ├── foundation/             # Base use cases, async state wrappers, typedefs
│   ├── network/                # HTTP client wiring, interceptors, error mappers
│   └── services/               # Device/platform services (storage, share, vibrator)
│
├── features/ (or modules/)     # Self-contained business features
│   └── <feature_name>/
│       ├── data/               # Models, remote/local datasources, repository impls
│       ├── domain/             # Entities, repository interfaces, use cases
│       ├── presentation/       # State controllers, pages, widgets
│       └── README.md           # Portable feature documentation & export guide
```

## 3. Layer Communication Rules
1. **Presentation -> Domain:** Presentation interacts with business logic exclusively via Use Cases or State Controllers. Never import Data Sources directly into Presentation.
2. **Domain Layer Independence:** Pure Dart. Zero UI imports (`flutter/material.dart` is prohibited in `domain/`).
3. **Data -> Domain:** Repository implementations map raw DTOs / JSON models to Domain Entities before returning.
4. **Observer Quarantine:** Any event bus or UI observer must live strictly within Presentation. Never import observer hubs inside `domain/` or `data/`.
